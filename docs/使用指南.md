# Delomu 使用指南

Delomu 是 AI 前線部署工程師：幫 AI 新創把產品導入客戶。agent 負責起草每一步，工程師負責核准、修改或退回。沒有人核准的草稿，不會改到任何東西。

## 一、打開產品（網頁）

本機的示範伺服器跑在 Docker 裡，容器名稱 `delomu-demo`。

| 要做什麼 | 指令 |
| --- | --- |
| 開啟 | `docker start delomu-demo` |
| 關閉 | `docker stop delomu-demo` |
| 看狀態 | `docker ps --filter name=delomu-demo` |
| 看記錄 | `docker logs delomu-demo --tail 50` |

開啟後，用瀏覽器打開 <http://localhost:8080/login>，在「API key」欄位貼上 `demo-data/api-key.txt` 裡的金鑰，按「Sign in」。

`demo-data/` 資料夾放的是示範用的資料庫、伺服器密鑰和登入金鑰。它不會進 git，請不要分享。

### 網頁上有什麼

| 頁面 | 用途 |
| --- | --- |
| Organizations | 你能管理的組織（客戶公司，或合作夥伴底下的客戶） |
| 組織頁 | 這個客戶的所有部署，以及稽核紀錄入口 |
| 部署頁 | 每次測試的結果：通過幾個、是否通過驗收、用哪個模型評分。點測試編號，打開給客戶看的驗收報告 |
| Drafts | agent 的草稿。可以直接在框裡修改內容，寫備註，再按 Approve（核准）或 Reject（退回） |
| Audit log | 誰在什麼時候做了什麼。每個部署的紀錄都是雜湊鏈，被改過會顯示「broken」。可以匯出 CSV |

**第一個練習：** 進入 support-bot → Drafts，看 agent 寫的「修正建議」（步驟 4），覺得對就按 Approve。之後在 Audit log 會看到你核准的紀錄。

## 二、一個客戶從頭到尾（指令列）

指令都在 `C:\Users\OS\Desktop\delomu` 下執行。`<dir>` 是部署資料夾。

**事前準備：** agent 和評分需要模型金鑰，二選一：

- Claude：設定 `ANTHROPIC_API_KEY`
- Meta：設定 `MODEL_API_KEY`（或 `LLAMA_API_KEY`）

都沒設的話，agent 會停下來並說明原因；評分則改標為「需要人工檢查」。

| 步驟 | 指令 | 說明 |
| --- | --- | --- |
| 0 建立 | `node bin/delomu.mjs init <dir> --customer "客戶名"` | 建立部署資料夾 |
| 放資料 | 把客戶的政策文件、API 文件、工單匯出檔放進 `<dir>/inputs/` | agent 只能讀這個資料夾 |
| 1–3 起草 | `node bin/delomu.mjs agent <dir> all` | 起草資料對應、整合設定、測試案例 |
| 審核 | `node bin/delomu.mjs drafts <dir>`，再執行 `node bin/delomu.mjs review <dir> <草稿編號> approve --by 你的名字` | 也可以用 `reject`。加 `--content 檔案.json` 可以先改內容再核准 |
| 4 測試 | `node bin/delomu.mjs run <dir>` | 跑客戶的 AI，產出 `runs/<時間>/report.html` |
| 4 修正 | `node bin/delomu.mjs agent <dir> fixes` | 把失敗歸類成原因和修法，核准後寫進 `fixes.md` |
| 5 上線報告 | `node bin/delomu.mjs agent <dir> launch-report` | 核准後寫進 `launch-summary.md` |
| 記工時 | `node bin/delomu.mjs log <dir> 3-test-set 1.5 "備註"` | 每個人工步驟花多久 |
| 關卡 1 | `node bin/delomu.mjs compare-hours <根資料夾>` | 第 5 個客戶的工時是否少於第 1 個的一半 |
| 稽核 | `node bin/delomu.mjs audit <dir> --verify` | 檢查紀錄有沒有被改過 |

`node bin/delomu.mjs help` 會列出全部指令。

## 三、上線後：監測與計費（v2）

| 要做什麼 | 指令 |
| --- | --- |
| 檢查一次（適合排程） | `node bin/delomu.mjs watch <根資料夾> --once` |
| 一直監測 | `node bin/delomu.mjs watch <根資料夾>` |
| 當月帳單 | `node bin/delomu.mjs usage <根資料夾> --month 2026-11` |

測試集、客戶 AI 的設定或模型版本一有變化，就會自動重跑；沒變化時，預設每 24 小時跑一次。重跑後和上一次比對，找出變差的案例。若在 `delomu.json` 設了 `monitor.webhookEnv`，會發 Slack 警報，同一批問題不會重複通知。

計費方式：每家客戶每月 3,000 美元，每個運作中的部署每月加 500 美元。數字可以用 `pricing.json` 改。

## 四、知識庫（v4）

客戶書面同意後，在 `delomu.json` 加上：

`"library": { "consent": true, "consentedBy": "誰同意的", "consentedAt": "YYYY-MM-DD" }`

接著設定 `DELOMU_LIBRARY_SALT`（16 個字元以上的密語）。

| 要做什麼 | 指令 |
| --- | --- |
| 收錄（自動去除個資） | `node bin/delomu.mjs library harvest <dir> --library <知識庫資料夾>` |
| 搜尋 | `node bin/delomu.mjs library search "退款" --library <知識庫資料夾>` |
| 替新客戶建議案例 | `node bin/delomu.mjs library suggest <新客戶dir> --library <知識庫資料夾>` |
| 客戶要求刪除 | `node bin/delomu.mjs library forget <來源編號> --library <知識庫資料夾>` |

「建議案例」一樣會變成草稿，要有人核准才會加進去。

## 五、正式部署到客戶的雲端（v3）

給客戶自架時，見 [v3.md](v3.md)。重點：

- `DELOMU_KEY_PEPPER` 一定要設，並放在密鑰管理工具裡。
- 預設不允許「指令」型的客戶 AI，只允許 HTTP，避免租戶在伺服器上執行指令。示範環境為了跑假的機器人，才打開 `DELOMU_ALLOW_COMMAND_TARGETS=1`。
- 目前只支援單台伺服器。
