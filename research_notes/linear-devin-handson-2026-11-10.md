# Linear app + Devin hands-on vs Grapim (2026-11-10)

Follows `unicorn-handson-2026-11-10.md` (Vercel app + landing pages). This note does not repeat it. That note said Linear was not signed in; today it was.

Method: Claude in Chrome, the user's real Chrome, one new tab (closed after). Read-only: I opened views, menus and popovers and closed them with Escape. Nothing was created, edited, toggled, commented, assigned or dismissed. In Ctrl+K I typed only the word "issue" and pressed Escape. Measurements come from `getComputedStyle`, `document.getAnimations()`, element boxes and screenshots. Viewport 1280 x 585.

## Limitations (plain)

- **Linear workspace is almost empty**: 1 team, 4 onboarding issues that Linear seeds itself, 0 projects, 0 cycles, 1 inbox notification. So I **did not observe** project health, progress bars, cycle burn-up or a busy inbox. Where I mention them, I say what the UI offers (menus, display properties), not what it draws.
- I did not click the inbox notification, because opening it marks it read.
- **Devin is signed in** (org on the free plan, credits used up). There is one old session that can no longer resume. So I **did not observe a live run** (steps streaming in). I saw a finished session, its step groups, the right-hand panel and the Review inbox. The live view described below comes from devin.ai's landing replica, and I mark it that way.
- I did not close Devin's "SWE-2 Flash" promo card, so it covered part of the right panel in screenshots. I read that panel through the DOM instead.
- `devin.ai` sends a signed-in user to `app.devin.ai`. I reached the landing page by going to `/pricing` and clicking the logo.

## What Grapim should learn (observed, mapped to Grapim)

1. **Step groups, not a log.** Devin hides the work behind "Worked for 4m 57s +18" and opens to one-line past-tense steps with a per-step result. Grapim's check run has a natural version: "Checked 16 messages for rule 3 · 2 broke" → expand → "Sent 'I want a refund after 45 days' · Agent offered refund · Broke §7".
2. **The proof sits on the hand-off object.** Devin's PR card carries a plain "Devin's analysis", a test recording 2/5 and "5 tests passed". Grapim's sign-off link and evidence pack should carry the same three things: a 2-line summary, a replayable transcript, and an "N of N rules kept" count.
3. **State-grouped review inbox with coloured chips** (Devin `/review`: Waiting for reviewers / Drafts, "Ready to merge" / "CI failing"). That is exactly what Grapim's Home "Waiting for your decision / Waiting on the client" is reaching for. It also loads chips as skeletons and fills them in later.
4. **A command menu scoped to what is selected** (Linear): a chip for the selected object, its actions with single keys, and a Tab switch to the AI.
5. **Same sidebar everywhere, with a count on Inbox** (Linear). Both products also put a status line under each session or issue in the sidebar (Devin: "Exceeded limit · PRs 1 1").
6. **Empty states show a filled sample** (Linear Reviews' sample PR, 01/03 guided sections). Vercel did the same (previous note). Grapim's Live and sign-off empty states should too.
7. **Guided review, one section at a time** (Linear Diffs). That maps directly to a client legal reviewer going through Grapim rules one at a time.
8. **Trigger → action templates** (Linear Loops, Devin Automations). That maps to Grapim monitoring: "Every live conversation → check refund rules → post to Slack".
9. **Motion is fast and functional**: 150ms colour and opacity, 0ms hover-in, 150ms hover-out, no page spinners after the first load.

## What Grapim should build in its own way (ranked by what a deployment lead notices in a demo)

1. **Check results page → a live run timeline.** While a check runs, show collapsed groups per rule ("Rule 3 · Refunds over $500 · testing 4 of 16 messages…"), and when it finishes, "Rule 3 · 16 messages · 2 broke". Expanding one shows one line per test message with Kept/Broke and opens the transcript. This replaces today's 8-tile grid plus the duplicated "Kept" list. (Devin's "Worked for … +18" groups. Grapim's version counts messages and breaks, not code lines.)
2. **Home becomes an inbox grouped by what needs whom**: "Needs your decision" (drafted fixes), "Waiting on client" (open sign-off links, with when each was opened), "Live alerts", "Done". Each row shows client · agent · one coloured state chip ("Fix ready to approve", "2 rules broken", "Signed off"), plus an age. This also settles the two-overviews problem from the previous note. (Devin `/review`, Linear Inbox. Grapim's sort order is fixed by urgency, with no switches to turn on.)
3. **The sign-off link carries its own proof card.** At the top of the client page and on the Rollout card: a 2-line "What we checked" summary in plain words, "8 of 8 rules kept · 16 messages each", and one replayable example conversation (a transcript stepper "2 / 5"). (Devin's "Devin's analysis" + test recording 2/5 + "5 tests passed".)
4. **Ctrl+K command menu**, scoped to the current object: on an agent, "Run check" (R), "Create sign-off link", "Copy sign-off link", "Open evidence pack", "Approve fix"; globally, "Open client…", "Add client", "Search rules and policies…". Show the key next to each action, plus a Tab mode for questions ("which clients are waiting on legal?"). (Linear.)
5. **Client sign-off page → guided review, one rule at a time.** "Rule 3 of 8 · Refunds" shows the quoted policy text, what we tested and the result, then Next (↓/J), with Approve or Ask a question per rule and a "3 / 8" counter. (Linear's Guided reviews and its issue "1 / 4" stepper.)
6. **A fixed sidebar with live counts**: Inbox (n), Clients, Agents, Audit log, Billing on every page. Under each client, a one-line status ("Waiting on Harbor Bank legal · 2d"). Hover tooltips show "G then I" style shortcuts. (Linear sidebar, Devin session rows.)
7. **Agent page → a right rail of properties plus an activity feed.** Right rail: client, agent endpoint, policies (count), last check, sign-off status, Live on/off. Empty fields read as actions ("Connect help desk", "Add policy"). The main column ends in a plain-language activity feed mixing people and Grapim ("Grapim found 2 breaks · 9 Nov", "You approved fix · 9 Nov", "Harbor Bank opened link · 10 Nov"). (Linear issue detail.)
8. **Live tab → monitors as trigger → action cards**: "Every live conversation → check refund rules → alert #support-ai in Slack", with templates and a "Suggest monitors from this client's policies" card. The empty state shows a filled sample of a flagged conversation. (Linear Loops, Devin Automations' "Suggest automations for me".)
9. **Loading: skeleton chips, not blank pages.** The inbox and client lists render titles immediately and show status chips as grey pills until the check state arrives. Use 150ms colour and opacity transitions and an instant hover-in. (Devin `/review`, Linear transition variables.)
10. **Landing: a live replica of the run, with Grapim's own numbers.** Under the hero, an HTML replica of item 1 (rule groups ticking from "testing 4/16" to "2 broke" to "Fixed · 0 broke"), with a numbered "01 Read the client's policies / 02 Test / 03 Fix / 04 Client signs off / 05 Monitor" section after it, each step a real UI card. (Devin landing: replica right under the CTAs, timestamped "Testing 3/12" checklist, numbered 01–04 steps, a dated "Recently shipped" list as a sign that the product is alive.)

Not observed and not claimed: Linear project health or progress drawings, cycle graphs, a busy inbox, priority-inbox ordering; Devin streaming steps live in the app (seen only in the landing replica); what the tick strip in Devin's conversation does.
